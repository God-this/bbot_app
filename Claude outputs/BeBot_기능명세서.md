## 1. 시스템 구성

| 구분 | 기술 |
| --- | --- |
| 프론트엔드 | Flutter 3.x (provider, flutter_markdown, youtube_player) |
| 백엔드 | FastAPI + Uvicorn, LangGraph RAG 파이프라인 |
| LLM | OpenAI gpt-5.4-mini (기본) / Upstage Solar / Ollama — `PROVIDER`로 선택 |
| 데이터 | PostgreSQL + pgvector (문서 벡터, 사용자·대화, 성경 원문 `bible_krv`) |
| 캐시 | Redis (정확 일치 캐시 + 시맨틱 캐시, 요청 제한) |
| 모니터링 | Langfuse (트레이스·가드레일·구절 판정 기록) |
| 인프라 | AWS EC2 (운영, main만 배포) · emptycan (스테이징) |

**요청 흐름**

```
사용자 질문
 → 요청 제한(분당 15회) → 질문 재구성(직전 대화 반영)
 → 캐시 조회 ──(히트)──→ 구절 재검증 → 응답
 → 입력 가드레일(Moderation + LLM 판정) ──(차단)──→ 안내 문구
 → 검색(웹·도서·영상) → 1차 필터 → 재정렬 → 충분성 판정
     └ 부족하면 질문 재작성 1회 → 그래도 부족하면 fallback 안내
 → 답변 생성(스트리밍) → 성경 구절 검증 → 출처 전송 → 대화 저장 → 캐시 저장·평가 큐 적재
```

## 3. 기능 상세

### 3-1. 인증 (AUTH)

| 항목 | 내용 |
| --- | --- |
| 방식 | 소셜 로그인 → 백엔드가 사용자 upsert → JWT 발급 (유효기간 7일) |
| 제공자 | `google` / `naver` / `kakao` / `guest` — 응답의 `provider` 필드로 구분 |
| 웹 로그인 | 네이버·카카오는 Redirect URI 콜백으로 code 교환 (`/naver/web`, `/kakao/web`) |
| 게스트 | 기기 `device_id`를 식별자로 사용. 로그인 화면 버튼은 주석 처리 상태 |
| 권한 | `role` = `user` / `admin`. 관리자 API는 `require_admin`으로 보호 |

**규칙**

- 게스트 여부는 이메일·닉네임이 아니라 `provider == 'guest'`로 판단한다. (카카오는 동의항목에 따라 이메일이 없을 수 있음)
- 닉네임이 비면 게스트는 "게스트", 회원은 "사용자"로 표시한다.
- 로그인 화면 하단: "로그인하면 서비스 이용약관에 동의하는 것으로 간주합니다."

### 3-2. 채팅 (CHAT)

| 항목 | 내용 |
| --- | --- |
| 입력 | 빈 질문은 400. 입력창 안내 "BeBot에게 무엇이든 물어보세요" |
| 환영 화면 | "반가워요, 비봇이에요! 무엇을 도와드릴까요?" + 추천 질문 (탭하면 바로 전송) |
| 스트리밍 | `text/event-stream`. 토큰 → `[DONE]` → `[SOURCES]{json}` → `[SESSION]id` → `[MESSAGE]id` 순 |
| 진행 표시 | 첫 토큰 전 "답변을 생성하고 있어요..." |
| 맥락 | 직전 1턴(질문 + 답변 앞 300자)으로 후속 질문을 독립 질문으로 재구성. 재구성된 질문도 함께 저장 |
| 저장 | 출처 수신 직후 대화 저장 → `[MESSAGE]`를 먼저 보내 피드백 버튼이 바로 동작하도록 함 |

### 3-3. 답변 생성 — RAG 파이프라인 (RAG)

LangGraph 노드: `route → retrieve → judge_stage1 → rerank → judge_stage2 → generate` (실패 시 `rewrite` / `fallback`)

| 단계 | 내용 |
| --- | --- |
| retrieve | 웹 문서·도서 페이지·영상 자막 구간을 병렬 벡터 검색 (소스별 top 5), 중복 제거 |
| judge_stage1 | 코사인 유사도 0.3 미만만 제거하는 느슨한 예비 필터 |
| rerank | 재정렬 모델로 상위 5개 선정 |
| judge_stage2 | 구조화 출력으로 sufficient / partial / insufficient 판정. insufficient만 재작성 |
| rewrite | 질문 재작성 후 재검색. **전체 실행에서 최대 1회** |
| fallback | 재시도 소진 시 LLM 호출 없이 "제공된 자료만으로는 충분히 신뢰할 수 있는 답변을 드리기 어렵습니다…" |
| generate | 영상 → 웹 → 도서 순으로 컨텍스트 조립(문서당 800자), 질문 언어와 같은 언어로 답변 |

### 3-4. 출처 (SRC)

- 답변 아래 `출처 N건` + 웹 / 책 / 영상 태그.
- 출처 시트: 영상 자료 · 웹사이트 자료 · 책 자료로 구분.
- 영상: 앱 안에서 유튜브 플레이어로 해당 구간(`startTime`)부터 재생. 웹은 iframe 플레이어.
- 도서: 페이지 이미지를 `/images` 정적 경로로 제공.
- 임시 조치: 특정 도서는 페이지 대신 구매 링크로 노출하는 분기가 있음 (현재 주석 처리).

### 3-5. 안전 · 가드레일 (SAFE)

| 단계 | 내용 | 장애 시 |
| --- | --- | --- |
| 요청 제한 | 사용자별 분당 15회 초과 시 429 "요청이 너무 많습니다…" | Redis 없으면 통과 |
| Moderation | OpenAI `omni-moderation-latest`로 유해 콘텐츠 탐지 | fail-open |
| LLM 가드레일 | 주제 이탈(off_topic)·탈옥(jailbreak) 판정, "애매함"을 별도 선택지로 둠 | fail-open |

- 차단 시 사유별로 준비된 안내 문구만 노출 (LLM이 쓴 사유는 로그에만).
- 가드레일은 캐시 미스일 때만 실행 (캐시에는 통과한 답변만 있음).

### 3-6. 성경 구절 검증 (BIBLE) 🚧

> 교수님 피드백(2026-10-20)으로 "답변 먼저 생성 → 포함된 구절 사후 검증" 구조로 변경. 기존 방식(답변 전 도구 강제 호출, 평균 66초)은 연결 해제. 상세: `design/답변생성후_구절검색.md`

| 항목 | 내용 |
| --- | --- |
| 원문 | 개역한글 31,101절. 운영 DB `bible_krv` 장 단위 조회 + 메모리 캐시(512장), 실패 시 `bible.txt` |
| 검출 | `"본문" (책 장:절)`, 괄호 출처, 문장 속 주소, `N절에서 M절까지` 범위 표기 |
| 처리 | 3절 이하: 본문이 다르면 원문으로 교체 · 4절 이상: 존재만 확인, 틀린 본문은 빼고 주소만 · 없는 구절: 인용째 제거 또는 "성경"으로 치환 · 장만 언급: 장 존재만 확인 |
| 참고 구절 | 주소만 언급된 3절 이하 구절 원문을 답변 끝에 최대 3개 |
| 맥락·주소 판정 | LLM은 판정(ok / wrong_ref / quote_wrong / not_found / context_mismatch)만, 수정은 코드. 기본 **shadow** — 답변에는 반영하지 않고 Langfuse·로그에 기록 |
| 캐시 답변 | 꺼낼 때 code 방식으로 재검증 |
| 성능 | code 검증 평균 완료 4.1초 (LLM 재작성 방식 7.7초 대비) · 판정은 답변당 평균 3.3초, 전송 후 별도 스레드 |

### 3-7. 대화 기록 (HIST)

- 사이드바 "대화 기록": 세션 목록, 탭하면 메시지 불러오기 ("대화를 불러오는 중...").
- 세션 삭제: 확인 다이얼로그 후 삭제. 기록이 없으면 "저장된 대화가 없습니다".
- 새 대화: "현재 대화 내역이 삭제됩니다. 새 대화를 시작할까요?" 확인 후 시작.
- 사이드바 하단에 닉네임·이메일, 로그아웃.

### 3-8. 피드백 (FB)

| 항목 | 내용 |
| --- | --- |
| 답변 평가 | 👍👍(2, 아주 좋아요) / 👍(1) / 👎(-1) / 취소(null) |
| 👎 의견 | "어떤 점이 아쉬웠나요?" — 선택 입력, 최대 2,000자 |
| 저장 | `chat_messages.feedback`은 현재 선택값, `message_feedback`에는 평가할 때마다 이력 추가 (취소는 기록 안 함) |
| 의견 보내기 | 채팅 화면의 "의견 보내기" 버튼 |

### 3-9. 답변 캐시 (CACHE)

| 항목 | 내용 |
| --- | --- |
| 종류 | 정규화 질문 정확 일치 + 임베딩 시맨틱 캐시 (유사도 ≥ 0.96) |
| 유효기간 | 90일, 히트 시 갱신 |
| 거절 표시 | 평가에서 탈락한 답변은 30일간 캐시 제외 (문서 보강 후 재도전) |
| 개인정보 | 캐시에는 대화 이력을 저장하지 않음 (출처 키 화이트리스트) |
| 저장 시점 | 출처 전송 후 백그라운드 (응답 지연 없음) |

### 3-10. 관리자 (ADM) ⏸️

- 관리자 대시보드 "영상 상태 관리": 전체 / 정상 / 문제 개수와 영상별 상태, 다시 확인 버튼.
- 백엔드 `VIDEO_HEALTH_CHECK_ENABLED = False` → 현재 상태 확인이 실행되지 않음 (켜면 주 1회 자동 확인).
- 진입: 채팅 화면의 "관리자 인증" 다이얼로그 (비밀번호 입력).

### 3-11. 운영 · 평가 (OPS)

- Langfuse: 질문 재구성 · 가드레일 · 그래프 노드 · 구절 판정(`verse-judge-shadow`)을 하나의 트레이스로 기록.
- RAGAS 평가 큐: 답변마다 `qa_eval_queue`에 적재, 평가는 별도 프로젝트(`bebot-cache-eval`)가 수행. 평가 입력에서는 성경 인용을 떼어냄(성경은 검색 문서에 없어 faithfulness가 깎이므로).

### 3-12. 웹 앱 (WEB)

- 이름·파비콘·아이콘·앱 내 로고를 BeBot으로 통일 (`BebotLogo` 공용 위젯).
- PWA 설치 버튼 제거, 파비콘 `?v=N`으로 캐시 갱신.
- 상세: `troubleshooting/웹앱_이름_아이콘_브랜딩.md`

## 5. 주요 설정값 (`.env`)

| 설정 | 기본값 | 설명 |
| --- | --- | --- |
| `PROVIDER` | openai | LLM 제공자 (openai / upstage / ollama) |
| `VERSE_VERIFY_MODE` | code | 구절 원문 대조 (code / off) 🚧 |
| `APPEND_REFERENCE_VERSES` | true | 참고 구절 덧붙이기 🚧 |
| `VERSE_JUDGE_MODE` | shadow | 맥락·주소 판정 (shadow / apply / off) 🚧 |
| `VERSE_CONTEXT_ACTION` | log | 맥락 불일치 처리 (log / remove) 🚧 |
| `BIBLE_SOURCE` | db | 성경 원문 출처 (db / file) 🚧 |

`.env`는 서버 시작 시 한 번 읽으므로 변경 후 재시작 필요.
